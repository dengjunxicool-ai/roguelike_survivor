3. **性能对照**：前后使用相同场景驱动、mage 初始构筑、seed 618、高血量移动辅助，禁用玩家自动攻击，保留同驱动 dash，原速真实渲染，串行采满 180 秒普通阶段与单独 90 秒 Boss 战。两版本夹具均跳过所有升级/奖励选卡，Boss 等待激活时清空奖励待办、不选择祝福；记录完整初末 loadout，要求每局不变且前后相同。真实选卡和祝福由流程矩阵与准备弹窗验证。场景计数逐帧记录；性能只适用于该固定压力场景，不覆盖成长/祝福后的构筑、正常玩家输出或其他地图。

构筑从当前 `GameData` 的合法技能池生成：保留角色初始神系，选三种不同的第二神系，每系各加入一个合法 cast/passive；完整技能定义、ID、等级、稀有度和初末 loadout 保存到每局 JSON。种子为 618–622，未以旧技能版本写死组合。

## 性能对照结果

旧 `stage-c-performance/before-*` 使用较早驱动，仅为先导；`stage-c-performance-final` 在发现深渊压力问题后中止。`stage-c-performance-final2` 基线通过自动选卡学会了新技能，且新版 Boss 准备奖励会阻塞等待，不能证明同构筑，亦不计最终证据。固定构筑首轮采用 `stage-c-performance-fixed-final` 四份样本及相同版本的 `sample_monster_performance.gd`，发现退化后再定位、优化和复测。Boss 保持实际初始血量，没有人为切换阶段；最终 90 秒只观察到阶段 1，不能当成三阶段峰值压力的完整性能覆盖。

关键分位恶化超过 10% 时必须定位和复测，不以“怪多”直接豁免。当前只作工程压力测量，未测所有地图和输出型构筑。

首轮固定构筑的四次引擎运行均 exit=0、stderr 空，初末技能均为 fireball / fire_dash_blazing_run 且不变。普通阶段 p50/p95/p99 为 0.907/6.401/14.228 → 0.915/6.793/15.719 ms，其中 p99 **+10.479%**，超过门槛，不能只凭四次进程 PASS 判性能通过。Boss 为 0.766/4.937/6.761 → 0.732/2.984/5.671 ms，未触发门槛。原 comparison.json 保留该回归记录。

定位先测当前生产波次解析与快照路径各 10,000 次：平均 70.28 / 76.65 微秒/次，日志 `E:/codex/monster-system/stage-c-hotpaths/current.log`。这是无战斗实体的微测，不证明整场尾帧原因；没有据此引入缓存或调整玩法。后续启用已有 enemy_profile 分段计时，前后各重复采 180 秒普通阶段，证据目录 `E:/codex/monster-system/stage-c-performance-profile`。分段计时本身有开销，与首轮分别报告。
