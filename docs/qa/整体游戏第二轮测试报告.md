## R2 01 永久升级全部免费

**复现：** 使用新隔离存档，余额为 0；进入局外强化，依次购买生命强化、拾取强化、幸运强化和战斗直觉，并继续购买至满级。

**实际：** 四项首次费用均为 0，购买成功且余额仍为 0。继续购买后分别到达 20、40、10、1 级，共 71 级，全部不扣灵魂石。800×600 的局外升级截图中也显示“强化 0”。

**预期：** 永久升级按明确费用消耗资源；如某项设计为免费，应显式标记免费，不能因缺字段自动变成免费。

**原因与位置：** [永久升级配置](../../data/upgrades/upgrades.json:131)没有 `cost_base` 和 `cost_growth`；[费用读取](../../scripts/game/save_manager.gd:267)将缺失基础费用视为 0，[购买条件](../../scripts/game/save_manager.gd:284)因此允许零余额购买。

**修复建议及验收：** 补齐经设计确认的费用；校验配置缺失，明确区分免费和错误配置。验证零余额、余额不足、余额刚好、不同等级费用和满级拒购，确认扣款与升级存档一致。

**证据：** [经济观测](E:/codex/game-qa-round2-20261011/economy-observations.json)、[运行日志](E:/codex/game-qa-round2-20261011/economy-02/result.log)、[界面截图](E:/codex/game-qa-round2-20261011/visual/screenshots/meta-english-800.png)。

## R2 02 战斗直觉无实际收益

**复现：** 新局记录 Boss 祝福选项数及对 Boss 的伤害 modifier；购买 `meta_combat_intuition`，调用生产永久属性应用入口，再次生成祝福并查询对 Boss 的伤害 modifier。

**实际：** 永久聚合数据含 `pre_boss_blessing_options_add=1`，但购买前后祝福均为 3 项，对 Boss 伤害查询为空。配置描述写“BOSS增伤1”，效果字段却是额外祝福选项，两个方向均没有实际收益。

**预期：** 升级提供明确、可观察的收益，描述和实现采用同一语义。

**原因与位置：** [战斗直觉配置](../../data/upgrades/upgrades.json:269)使用 progression 属性；[奖励池](../../scripts/upgrades/run_reward_pool.gd:7)固定裁切到 3 项，没有消费该永久加值。伤害查询也没有相应 Boss 增伤。

**修复建议及验收：** 先确定采用 Boss 增伤还是增加候选卡，再接通对应消费端和 UI。购买前后用同一受控输入比较，确认收益持久化并在新局生效。

**证据：** [永久效果观测](E:/codex/game-qa-round2-20261011/meta-effect-observations.json)的 `intuition`、[运行日志](E:/codex/game-qa-round2-20261011/meta-effect/result.log)。

## R2 03 遗物奖励生成不可领取卡

**复现：** 通过生产 `RelicManager.add_relic` 持有三件遗物，生成精英奖励并选择遗物卡。另在仅持有 `ember_badge`、还有空槽时生成奖励，检查重复遗物。

**实际：** 满槽情况下，40 个奖励池种子中有 19 个最终三卡列表包含遗物卡；派发这些卡均返回 `handled=false`。有空槽但已持有 `ember_badge` 时，80 个种子中有 5 个仍生成同件遗物。UI 选择失败后静默保留弹窗，没有解释；另外两张卡仍可选择，因此未观察到整局锁死。

**预期：** 满槽时过滤遗物，未满槽时过滤已持有遗物；玩家看到的奖励应可领取。

**原因与位置：** [遗物随机候选](../../scripts/upgrades/run_reward_pool.gd:109)不接收玩家上下文，直接从完整遗物池抽取；[遗物添加](../../scripts/relics/relic_manager.gd:30)拒绝重复和超容量；[选择回调](../../scripts/ui/modals/run_choice_modal_controller.gd:853)在 `handled=false` 时直接返回。

**修复建议及验收：** 生成阶段按容量、已持有和合法定义过滤，无可用遗物时回退到其他奖励。覆盖 0、1、2、3 件持有、重复抽取和候选耗尽；不能提前消费失败奖励。

**证据：** [满槽观测](E:/codex/game-qa-round2-20261011/boundary-observations.json)的 `full_relics`、[重复观测](E:/codex/game-qa-round2-20261011/lifecycle-observations.json)的 `duplicate_relics`。

## R2 04 治疗统计使挑战错判

**复现与实际：**

1. 75 / 75 满血选择 25% 治疗奖励，血量没有变化，但 `healing_used=19`。
2. 25 / 75 选择普通 `survival_heal` 升级，恢复到 55 / 75，`healing_used` 仍为 0。
3. 调用生产技能治疗动作，65 / 75 恢复到 70 / 75，治疗统计仍为 0；将该生产统计快照交给胜利结算后，“无治疗通关”被写入存档。

**预期：** 按统计器声明的实际治疗量累计，普通升级、技能和奖励采用一致口径；真实治疗后不能取得无治疗挑战。若设计要求“选择治疗即失格”，应另建事件计数，不能混用实际治疗量。

**原因与位置：** [奖励治疗](../../scripts/ui/ui_command_dispatcher.gd:120)记录理论恢复量，而非实际血量差；[普通升级治疗](../../scripts/player/player_modifier_applier.gd:66)和[技能治疗](../../scripts/skills/skill_action_modifier_executor.gd:9)没有调用统计入口。[无治疗挑战](../../scripts/game/run_progression_service.gd:163)仅检查 `healing_used`。

**修复建议及验收：** 统一治疗应用与统计，按实际恢复值记录，避免漏记或重复。覆盖满血、溢出治疗、普通升级、技能治疗及结算存档；生命上限增加是否视为治疗须单独定义。

**证据：** [边界观测](E:/codex/game-qa-round2-20261011/boundary-observations.json)的 `full_health_reward` 和 `upgrade_healing`、[生命周期观测](E:/codex/game-qa-round2-20261011/lifecycle-observations.json)的 `skill_healing` 和 `saved_no_heal_challenge`。

## R2 05 指定精英击杀挑战错判

**复现：** 用受控敌人对象向生产统计器记录一次 `shadow_hunter` 精英死亡，没有 `toxic_matriarch` 死亡；将该快照按毒雾墓地胜利结算。

**实际：** `toxic_fog_graveyard:defeat_toxic_matriarch` 被持久化为完成。独立判定检查中，任意 `elite_kill_count=1` 也能满足 `defeat_lava_golem` 和 `defeat_shadow_hunter`。

**预期：** 各挑战核对对应敌人 ID 的有效击杀，未击杀目标时不解锁。

**原因与位置：** [三个指定目标的判定](../../scripts/game/run_progression_service.gd:177)共用 `victory && elite_kill_count > 0`，没有读取目标 ID。这是受控统计输入下的结算缺陷，未声称本轮自动对局自然产生了错误目标组合。

**修复建议及验收：** 按敌人 ID 记录并查询击杀；区分真实击杀与离场清理。三个目标分别验证目标击杀、其他精英击杀、未击杀和失败结算。

**证据：** [持久化复现](E:/codex/game-qa-round2-20261011/progression-observations.json)的 `elite`、[三个目标判定](E:/codex/game-qa-round2-20261011/boundary-observations.json)的 `wrong_elite_objectives`。

**修复建议及验收：** 补充对应运行统计并接入挑战。对照测试纯闪电、仅穿透、仅弹射、二者都没有和失败结果，确认新判定持久化正确。

## R2 07 破势训练的效果与文案不符

**复现：** 从生产 Boss 祝福候选取得 `boss_control_blessing`，经生产命令分派器应用，检查效果定义和玩家属性。

**实际：** “破势训练”的标签为控制，影响范围为 Boss 韧性／生存；实际绑定 `survival_defense`，玩家护甲从 0 增为 2，没有控制或 Boss 韧性相关效果。

**预期：** 控制方向的祝福提供明确控制收益；如果保留护甲，应改为清楚的护甲奖励。

**原因与位置：** [祝福定义](../../scripts/upgrades/run_reward_pool.gd:66)复用了防御升级，却采用控制路线文案。

**修复建议及验收：** 确定效果后统一标题、描述、标签、影响范围和推荐理由；通过实际 Boss 目标验证收益范围，避免仅检查卡片可应用。

**证据：** [生命周期观测](E:/codex/game-qa-round2-20261011/lifecycle-observations.json)的 `control_blessing`。

## R2 08 拾取强化描述与数值不一致

**复现：** 记录新局有效拾取半径，购买一级 `meta_pickup` 并应用永久属性，再查询有效半径。

**实际：** 描述为“拾取范围+40%”；有效半径从 85 增为 88.4，倍率为 1.04，即增加 4%。

**预期：** 配置说明与运行效果一致，并明确每级增量。

**原因与位置：** [拾取强化配置](../../data/upgrades/upgrades.json:183)的说明写 40%，`pickup_radius` 的 `multiplier_add` 值却为 0.04。[有效半径](../../scripts/player/player_controller.gd:258)按该系数计算。

**修复建议及验收：** 依据设计选择修正文案或数值；核对一级、多级和满级累计，验证持久化与新局效果。

**证据：** [永久效果观测](E:/codex/game-qa-round2-20261011/meta-effect-observations.json)的 `pickup`。

## R2 09 损坏存档被设置写入覆盖

**复现：** 仅在隔离测试存档操作：创建 123 灵魂石、生命强化 2 级的配置，在文件首行插入 `corrupted=???` 制造解析失败，再将主音量保存为 55。

**实际：** `ConfigFile.load` 报解析错误后，`save_value` 仍执行保存。原文件被替换为只有 `[settings] master_volume=55.0` 的内容；灵魂石和生命强化等级均变为 0，原可供恢复的货币、成长文本丢失。

**预期：** 读取现有存档失败时保护原文件，恢复备份或拒绝覆盖，并给出可处理的结果。

**原因与位置：** [统一写入入口](../../scripts/game/save_manager.gd:29)忽略 `config.load` 和 `config.save` 返回值。解析失败时仍将不完整配置保存到相同路径。

**修复建议及验收：** 区分首次无存档与现有存档解析失败；失败不得覆盖，保留备份，保存成功后才确认持久化操作。覆盖文件头／中部损坏、缺文件、正常更新保留其他字段，以及写入失败。故障测试必须继续使用隔离目录。

**证据：** [覆盖前后文件内容](E:/codex/game-qa-round2-20261011/save-fault-observations.json)、[最终故障复现日志](E:/codex/game-qa-round2-20261011/save-fault-03/result.log)。日志中的解析错误是主动注入的条件；缺陷是错误之后继续覆盖进度。

## R2 10 英文设置后仍有主要控件显示中文

**复现：** 设置中选择 English，依次打开图鉴、局外升级和角色选择。800×600 真实渲染截图可复现。

**实际：** 设置和已绑定的页面标题能译为英文；图鉴返回按钮仍为“返回主菜单”，局外升级仍显示“灵魂石”“强化”“返回欢迎页”，角色选择的标题、返回和货币控件仍为中文。

**预期：** 如果 English 面向完整游戏操作，主要导航和操作控件应提供英文。玩法名称、描述的翻译范围可以另行制定。

**预期：** 同一已保存配置重复应用应得到一致结果；如果允许最大化，应明确保存或采用稳定的默认策略。

**原因与位置：** [窗口模式应用](../../scripts/ui/ui_settings_service.gd:21)在 false 分支按当前模式反向切换。该项通过设置服务重复应用复现，未观察到普通单次勾选全屏导致卡死。

**修复建议及验收：** 将“应用配置”改为确定目标模式，或增加独立窗口／最大化配置。覆盖冷启动、重复应用、全屏往返和窗口尺寸保持。
