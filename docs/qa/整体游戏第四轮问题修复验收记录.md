## 存档兼容和首次建档恢复

待补存记录新增 `requires_existing_save`。新用户尚未建立主档时记录为 false；首次主档提交时将这些记录改为依赖主档。没有该字段的旧 journal 按 true 处理，避免以空档消费旧奖励。普通设置和货币写入也遵守同一保护；显式成功重置进度仍更换 epoch 并淘汰旧记录。

首次建档存在待补存记录时，先写出完整 `save.cfg.tmp`，再将临时文件 SHA256 与主档依赖一起持久化到 journal，最后原子重命名主档。中断或重命名失败时保留临时文件；下一次启动只接纳哈希匹配的临时文件。主档已经提交、临时文件已消失而 journal 清理尚未完成时，若主档被外部移走，仍等待原档恢复，不生成空档。

显式重置仅在新主档成功提交后清空待补存与首次建档阶段。重置失败保留原状态；清理 journal 失败时，新主档的 UUID epoch 仍阻止旧奖励重放。[reset-with-stage 独立复验通过](E:/codex/game-qa-round4-fix-20261011/persistence/root-final-reset/result.log)。

读取暂时失败的 journal 重新可读后，优先保留磁盘已有凭据，再合并内存新增凭据。等待 journal 恢复的结算在读取旧序号后才分配新序号。旧 journal 没有结束序号时按未知历史顺序 0 处理，不覆盖已具有较新序号的摘要。

实际受控结果：原档余额／局数／击杀 **100／7／111 → 135／8／153**；两次骷髅队长奖励恢复后余额 **170**，重复重放不重复到账。旧局 A 为 301 秒、42 杀，新局 B 为 22 秒、3 杀；补存 A 后累计 **9 局、156 杀**，最近摘要仍为 B。
