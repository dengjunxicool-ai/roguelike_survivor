# 火焰神系特效

已将 14 个基础火焰技能接入现有战斗对象的程序化展示接口。热核、火舌、熔岩、焦土和余烬由独立实例材质与固定几何批次生成；旧火球材质、纹理和赤焰龙图片保留作为兼容资源。神系融合独立技能不在本轮重设计范围，共享火焰对象自动使用新的展示。

## 技能映射

| 技能 | 展示与真实触发路径 |
| --- | --- |
| 灼热火球 | 热核火球、扭动尾焰；真实命中产生火星，实际燃烧和脚下火径分别展示 |
| 烈焰疾行 | 实际冲刺生成的连续火径、焦边、上升火舌 |
| 流星火雨 | 带焦黑热壳的陨石、长尾焰；真实落地对象留下火山口与燃烧地面 |
| 熔岩裂涌 | 与真实起点、长度、宽度和方向一致的熔岩带，焦壳和炽热裂隙 |
| 焚风旋涡 | 随真实区域移动的螺旋火柱，地面火环与上升余烬 |
| 赤焰龙 | 龙形轮廓、翼膜和热鳞；实际攻击目标决定吐息方向与长度 |
| 余烬狐群 | 火狐、火尾、朝实际目标的冲击动作；真实规范攻击和爆燃区域驱动命中反馈 |
| 炽燃专注 | 实际燃烧层数控制火舌强度，真实延长的状态寿命控制展示时间 |
| 过热施法 | 仅实际 5 秒临时属性来源有效时展示角色火焰，逐帧跟随角色 |
| 焦土亲和 | 真实火焰地面与目标燃烧状态叠加；不增加伪命中或独立伤害 |
| 燃爆连锁 | 每次真实主爆炸／派生爆炸回调提供中心和半径，热爆、冲击前沿与火星同步 |
| 余烬附着 | 独立的紧凑尖形余烬，跟随实际弹道方向与寿命 |
| 引燃核心 | 实际追加伤害动作后的紧凑范围爆燃；零伤害动作不生成爆燃 |
| 炼狱循环 | 实际死亡爆发动作提供爆燃范围，额外陨石共享陨石热壳与尾焰 |

## 生命周期与边界

- 投射物和区域由宿主传入年龄与范围，材质不使用 `TIME`，视觉配置／更新不调用全局随机函数。
- 状态与召唤动作使用暂停感知的 `delta`。火狐寿命计时器随战斗暂停；过热只读 `ModifierStore.get_timed_source_remaining`。
- 同路径池复用保留展示节点和实例材质，重设年龄、方向、风格、几何、透明度；回收立即停用。
- 区域通过 `geometry_shape` 的只读快照取得线形／十字／锥形边界。线形从真实起点沿真实方向延伸。
- 普通命中最多 24 个，范围爆燃最多 8 个，合计 32 个反馈节点；目标反馈节流表最多 128 项。
- 每个区域 24 个火星与 20 个火舌，各为一个固定网格批次。每个投射物共享 96 顶点余烬网格；位移材质有明确包围盒。
- 旋涡无纹理四边形使用顶点坐标归一化，避免依赖未提供纹理的 `Polygon2D` UV；所有层均尊重宿主淡出。
- 召唤物闲置时不重建吐息几何；冲击环只创建一次，实际攻击期间更新短时吐息。
- 已执行的燃爆／引燃／炼狱展示通过 `present_skill_effect` 直接通知表现层，不进入技能触发队列，不改变触发预算。

## 同步修复

原先余烬狐群的通用召唤没有基础伤害参数，也没有执行所属技能的 `summon_attack_hit` 规则，实际敌人生命不变。现在仅执行所属火狐技能适配后的规范攻击动作，保留等级成长、直接伤害、爆燃和燃烧，不广播到其他召唤技能。

真实 `EnemyBase` 回归中，双狐使生命 `10000 → 9928`，产生两个爆燃区域并叠加燃烧；同时学习赤焰龙不会触发龙的攻击规则。火狐 1.2 秒攻击间隔、有效目标判断、暂停与到期清理均已验证。伤害接口仍使用严格的 `DamagePacket`。

## 验证证据（2026-10-11）

Godot 4.6.3，无界面验证矩阵 30 项全部通过：火焰展示、真实伤害／状态／召唤、配置边界、规范内容、火球既有材质接口，以及寒霜与霜狼伤害回归。矩阵报告位于 `E:/codex/canonical-refactor/fire-school-vfx-final/results.json`。内容、Modifier 和 UTF-8 校验通过。

GPU 使用 NVIDIA GeForce RTX 5060、Vulkan Forward Mobile、1280×720。实际游戏场景安装 14 项基础火焰技能，逐项检查工厂挂接和可见像素差异，包含单独验证旋涡高火柱；实际范围伤害能降低真实敌人生命，暂停前后像素完全一致。另有投射物 107 项 GPU／生命周期检查、召唤物 GPU 暂停检查。

| 受控表现压力场景 | P50 帧间隔 | P95 帧间隔 |
| --- | ---: | ---: |
| 展示可见 | 2.139 ms | 3.753 ms |
| 仅隐藏渲染，仍更新展示状态 | 1.049 ms | 1.515 ms |

工作负载：8 个区域、128 个保留投射物宿主、16 个召唤展示和 16 个真实燃烧目标。两组敌人生命结果完全一致。可见组全部展示更新 P95 为 0.813 ms；单独无渲染采样中，16 个召唤的 CPU 姿态更新 P95 为 0.253 ms。报告位于 `E:/codex/fire-vfx/stress/{shown,hidden,cpu}/metrics.json`。

## 维护入口

- 规范展示配置：`data/combat/combat_objects.json`、`data/combat/status_effects.json`、`data/summons/summons.json`。
- 纯展示脚本：`scripts/effects/fire_*_effect.gd`；命中／过热协调：`scripts/visual/fire_combat_presentation.gd`。
- 无界面验证：`verify:fire-projectile-visuals`、`verify:fire-area-visuals`、`verify:fire-summon-visuals`、`verify:fire-feedback-runtime`。
- GPU 全技能检查：`tools/verify/verify_fire_school_rendered.gd`，传 `--capture-dir=E:/codex/...`。
- 压力检查：`tools/verify/verify_fire_vfx_stress.gd`，分别传 `--mode=shown`、`--mode=hidden`；`--headless --mode=cpu` 单独记录 CPU。GPU 各组串行运行，避免测量互相干扰。

启动 Godot 前将 `APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 指向 `E:/codex` 下的任务目录。所有新增验证输出保存在 E 盘。
